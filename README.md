# asa-it（朝IT）

工場の社内IT部門で働く若手が、**毎朝5分で、上司やベンダーの話についていけるようになる**ためのアプリ。
直近のITニュースを、応用情報技術者レベルの知識と「工場目線」に結びつけて、楽しく仕入れる。

- 目的は知識を身につけること。応用情報の試験対策ではない（応用情報レベルは知識量の目安）
- 利用者は自分1人。Androidスマホで使う

## 想定ユーザー

- IT歴2年目。基本情報技術者を取得済み。業務でのプログラミング経験はない（基本情報のB問題レベルの構文は読める）
- セラミックスメーカーの社内IT部門に所属
- 業務は工場向けシステム（生産管理、MES、設備連携）の要件定義・基本設計と、ベンダーコントロール
- インフラ、AI、クラウド、セキュリティ、開発手法、業界動向など、技術全般に苦手意識がある

## 1日分の中身（毎朝3本）

各ニュースのカードは次の4つでできている。

| 項目 | 内容 |
|---|---|
| 📰 ニュース要約 | 3行程度の要約と、元記事へのリンク |
| 🏭 工場目線 | 生産管理、MES、設備連携、OTセキュリティなど、工場の社内ITにどう関係するか |
| 🗣 ベンダーに聞ける一言 | 要件定義やベンダーとの打ち合わせで使える質問の例 |
| 🧠 理解度チェック | 背景にある技術や用語についての4択問題と解説 |

分野タグ: 工場・OT / インフラ / ネットワーク / クラウド / データ活用 / AI / セキュリティ / 開発手法 / 業界動向（各分野の中身は `categories.json`）

出題分野と1日の問題数（1〜5問）は、画面の「設定」から変更できる。設定は GitHub の `config.json` に保存され、翌朝のカードから反映される（`config.json` を直接編集してもよい）。

ニュースの取得元（RSS）: MONOist、ITmedia NEWS、ITmedia エンタープライズ、@IT、Publickey、IPA、JPCERT/CC

## 仕組み

```
GitHub Actions（平日の朝6時に自動実行）
  └ scripts/generate.py
      ① RSSから記事を集める（直近72時間、過去7日のカードと重複する記事は除外）
      ② Claude API（claude-opus-5-5）で3本を選び、カードを作る（構造化出力でJSONを返させる）
      ③ data/YYYY-MM-DD.json に保存し、data/index.json（日付の一覧）を更新する
GitHub Pages
  └ HTML/JavaScriptの画面（PWA）。フレームワークは使わない
Androidスマホ
  └ ホーム画面に追加して、アプリのように使う
```

- 費用の見込み: 1回約0.11〜0.12ドル（3問）。平日だけの実行で月350円前後。Haiku 5.5に切り替えれば月10円程度
- APIキーは `.env`（ローカル）と GitHub Secrets（Actions）に置く。コードやチャットには書かない

## 使い方（ローカル）

```
pip install -r requirements.txt
copy .env.example .env      ← 作った .env に自分のAPIキーを書く
python scripts/generate.py --dry-run   ← 記事集めだけ確認（無料）
python scripts/generate.py             ← カードを作る（APIを使う）
python -m http.server 8000             ← 画面を確認する（ブラウザで http://localhost:8000 を開く。止めるときは Ctrl+C）
```

画面のファイル: `index.html`（骨組み）、`style.css`（見た目）、`app.js`（動き）、`about.html`（アプリのしくみを説明するページ。画面右上の「しくみ」から開く）、`settings.html` / `settings.js`（設定画面。画面左上の「設定」から開く）。index.html を直接ダブルクリックで開くと、ブラウザの制限でデータを読み込めないため、上のようにサーバー経由で開く。

## 進め方と進捗

- [x] ステップ1: ローカルで記事を集め、Claudeでカードを作り、JSONに保存するスクリプト
  - 記事の取得（--dry-run）は動作確認済み
  - 2026-11-15 に初回のカード作成を実行し、品質を確認済み（data/2026-11-15.json）。1回の費用は約0.12ドル（入力 約7,600 / 出力 約4,300トークン）
- [x] ステップ2: JSONをカードで表示し、クイズに答えられる画面（HTML/JavaScript）を作る。回答の記録は端末に保存する
  - 画面（日付の切り替え、4択クイズ、正誤と解説、回答の記録をlocalStorageに保存、ダークモード対応）、しくみページ、設定画面（出題分野・問題数）を作成し、ブラウザで表示確認済み
  - 設定画面の「保存」は GitHub のリポジトリができるまで試せない（ステップ4の後に動作確認する）
  - 次はステップ3から再開する
- [x] ステップ3: GitHub Actionsで毎朝自動実行する
  - `.github/workflows/daily.yml`。2026-11-21 に手動実行で動作確認済み（作成→コミット→Pages公開）
  - 手動で作り直したいとき: GitHub の Actions タブ →「daily」→「Run workflow」、または `gh workflow run daily.yml`
  - main への push では公開（deploy）だけ動き、カードは作らない（費用がかからない）
  - 実行は**平日（月〜金）の朝6時だけ**（費用を抑えるため。2026-11-21 に決定）。GitHub Actions の時刻はUTCなので、cronは `0 21 * * 0-4`（日〜木の21時UTC＝月〜金の6時JST）
  - 注意: 設定画面から config.json がコミットされることがあるので、Actions はデータをコミットする前に最新を取り込む（pull）こと
- [ ] ステップ4: GitHub Pagesで公開し、PWAとしてAndroidのホーム画面に追加する
  - リポジトリ: https://github.com/takumim0731-prog/asa-it （公開。コミットのメールはGitHubの非公開用アドレス）
  - 公開済み: https://takumim0731-prog.github.io/asa-it/

## 開発メモ

- Windows版PythonでSSL証明書の検証エラー（CERTIFICATE_VERIFY_FAILED）が出たため、`truststore`でWindowsの証明書ストアを使うようにした
- クイズは計算問題を出さない（用語・仕組み・使い分け・対応を問う）。プロンプト（SYSTEM_PROMPT）で指示している
- Claudeにはarticle_id（候補の番号）で記事を選ばせ、URLとタイトルは元のRSSデータから埋める（URLの誤りを防ぐため）
- 進め方の方針: コードはClaudeが書き、要所にコメントで解説を入れる。各ステップの終わりに、関連する応用情報レベルの知識を一言ずつ振り返る
